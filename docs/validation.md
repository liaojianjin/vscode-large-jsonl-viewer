# 实现与验证记录

验证日期：2026-10-08（Asia/Shanghai）。版本：0.1.0。原始计划中的性能数字仍是目标，下面仅报告本次实际结果。

## 0.1.1 查看体验更新

默认开启自动换行，提供保留偏好的视图开关，作用于格式化 JSON、原始文本和超长记录的文本窗口。顶部改为单条紧凑工具栏，索引进度移至底部状态栏；折叠、查找、复制、导出收进“更多”，索引详情与控制可点击状态展开。

结构导航默认占约 20% 宽度、上限 200px，可收起。窄窗口默认收起导航；专注模式隐藏导航和状态栏。真实宿主使用包含连续中文/emoji 长字符串的记录，验证字符串实际产生多条显示行，并检查正文至少占视图 70% 宽度和 80% 高度。这是当前测试窗口的功能检查，不是完整 Webview 性能 p95。

## 功能与构建

- `npm run check`：TypeScript 严格类型检查通过。
- `npm test`：54 项通过，覆盖物理行边界、3 字节扫描块、LF/CRLF/BOM、空白行、UTF-8、缓存恢复/损坏、短读/短写、变化失效、严格 JSON、数值保真、重复 key、大数组的线性格式化、流式分页及取消。
- 实际稀疏文件测试在 `2^32 + 123` 字节处读取记录，确认文件位置未截断为 32 位。此用例不作为吞吐基准。
- 真实 VS Code 1.140.0 Extension Host 测试通过：`vscode.openWith` 进入只读 Custom Editor、源文件没有 TextDocument、125 行索引及随机访问成功、Monaco Webview 回传正文与结构渲染完成、关闭清理。
- 构建产物将主入口、索引/记录 worker、Monaco 和其 editor worker 一并打包，无 CDN 依赖。
- 实际宿主测试曾暴露首次打开同一行的请求竞态，已修复并复测。

## 1/10 GiB 基准

平台：macOS arm64、Apple M5 Pro、64 GiB 内存；基准 Node v26.7.0，实际扩展宿主为 VS Code 内置运行时。该内存配置高于计划参考环境的 16 GiB。文件位于 `/Volumes/WD_BLACK`，记录约 100 KiB，包含 Unicode、对象、数组和大整数。没有控制操作系统页缓存，下面是暖缓存结果，不能解释为物理磁盘读取速度。

| 文件 | 扫描块 | 索引耗时 | 暖读参考耗时 | 吞吐比 | 前 100 行边界就绪 | 随机记录后端 p95 | 峰值进程 RSS |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 GiB | 1 MiB | 106.5 ms | 62.4 ms | 58.5% | 2.1 ms | 15.2 ms | 53.1 MiB |
| 1 GiB | 4 MiB | 98.0 ms | 58.3 ms | 59.5% | 2.1 ms | 15.8 ms | 59.0 MiB |
| 1 GiB | 8 MiB | 101.4 ms | 61.7 ms | 60.8% | 2.8 ms | 17.2 ms | 67.0 MiB |
| 10 GiB | 4 MiB | 806.6 ms | 513.0 ms | 63.6% | 2.2 ms | 14.4 ms | 65.1 MiB |

1 GiB、4 MiB 块的吞吐比略低于计划的 60% 目标；这是单次暖缓存样本，未测 p95。默认保留 4 MiB：该样本比 1 MiB 更快，扫描缓冲比 8 MiB 更小。首次顺序读分别约 1.29 秒和 2.52 秒，显示缓存条件对结果有很大影响。

随机跳行使用固定 seed 42、30 次请求，包括 worker 启动、定位、读取、严格校验和保真格式化；未计入扩展激活、Webview IPC、Monaco 模型建立、绘制与导航可交互时间。索引内存指标是基准进程总 RSS，不能等同于“扫描缓冲+页缓存”或整个 VS Code 的内存。前 100 行指标也是索引边界就绪时间，不是 100 条记录完成渲染。

原始 JSON 结果保存在 `docs/benchmarks/`；复现实验会生成 `benchmark-results/`。日期字段为 UTC，应按本报告的 Asia/Shanghai 日期解读。

## 超长单条

测试流式生成巨大字符串，32 MiB 字符串样本另含百万项数组；记录 worker 不创建完整原文字符串、AST 或 Monaco 模型，只保留当前页的子项和显式容器栈。

| 字符串大小 | 文件记录大小 | 完整严格校验 | 首次结构进度 | 峰值进程 RSS | worker 取消 | 保留根子项 |
| --- | --- | --- | --- | --- | --- | --- |
| 32 MiB + 百万项数组 | 38.6 MiB | 290.5 ms | 14.7 ms | 115.2 MiB | 0.66 ms | 3 |
| 256 MiB | 256.0 MiB | 620.8 ms | 12.9 ms | 116.4 MiB | 0.59 ms | 3 |

“首次结构进度”不是巨大字符串字段就绪时间；字符串边界仍需扫描到关闭引号。RSS 为同一 Node 进程和线程的总量，包含运行环境及生成数据带来的基线；采样间隔 10 ms，不能证明没有更短的峰值。取消测试在记录 worker 首次消息后终止线程，未计入用户点击和 Webview 消息传递。

## 计划完成情况

P0–P3 的主要实现已落地，并通过本地内核测试与真实宿主打开验证。P4 已提供增量严格语法扫描、分页对象/数组、巨大值窗口、有界节点和 worker 取消；分页会重新扫描容器，没有为每个超长容器建立独立磁盘子节点索引。

P5 已提供测试工具、当前平台验证、初步后端性能记录及 VSIX 打包。以下验收仍待完成，不能由上述结果外推：

- 50/100 GB 有效 JSONL、短行/混合长行分布及受控冷读。
- VS Code 外壳、前 100 行正文可交互、折叠/导航的完整 p95。
- 数千次切行、多视图、长时间运行与 Webview 总内存计量。
- Windows、Linux、最低支持 VS Code 版本及远程扩展宿主。
- 磁盘满、崩溃/电源中断等真实环境故障注入。
